# ER Editor

Редактор **инфологических** (нотация Баркера, «мёртвые вороны смотрят на восток») и **даталогических** моделей баз данных. Программа читает схему SQLite, сама строит две диаграммы, а дальше вы правите их мышью и клавиатурой, как в draw.io, и экспортируете в PNG.

## Возможности

- Импорт схемы из любой базы данных SQLite: таблицы, столбцы, типы, первичные и внешние ключи, `UNIQUE`, правила `ON DELETE`. База открывается только для чтения и никогда не изменяется.
- Две диаграммы одного проекта: **инфологическая** (сущности, атрибуты `#` `*` `o`, связи Баркера) и **даталогическая** (таблицы, ключи PK / FK / U, типы, NOT NULL).
- Автораскладка по правилу «dead crows fly east»: «вороньи лапки» смотрят влево или вверх, линии связей обходят чужие сущности.
- Редактирование всего: названия, атрибуты и столбцы, типы, ключи, цвета, связи (кратность, сплошная и пунктирная половины, черты UID, имена концов), легенда, свободные надписи.
- Отмена и повтор (до 150 шагов), масштаб и прокрутка, привязка к сетке.
- Сохранение проекта в файл `.erd.json` и экспорт в PNG с масштабом ×1, ×2, ×3 и сглаживанием.
- **Рисование схемы с нуля.** Таблицы, типы столбцов и ключи рисуются прямо в окне, связи — стрелками от внешнего ключа к первичному (стрелку можно протянуть мышью от таблицы к таблице).
- **Проверка нормальной формы.** Выберите 1НФ, 2НФ, 3НФ или НФБК — программа только **проверяет**, соответствует ли нарисованная схема этой форме: показывает вердикт, подсвечивает проблемные таблицы и столбцы и объясняет, что исправить.
- **Создание базы данных.** По нарисованной схеме кнопка «Скачать БД» создаёт файл SQLite; «БД и модели» добавляет инфологическую и даталогическую модели в PNG и отчёт о проверке. Чекбокс «5 случайных записей» заполнит каждую таблицу правдоподобными тестовыми данными, согласованными с внешними ключами.
- **Веб-версия.** Тот же редактор работает в браузере (HTML + JavaScript, схема рисуется в SVG), а проверку нормальных форм, раскладку, создание базы данных и PNG выполняет небольшой Python-сервер: `python run_web.py`. Подробности — в разделе «Веб-версия».
- Окно **«О программе»** показывает это руководство прямо в программе.

## Установка и запуск

Нужны Python 3.9 или новее и библиотека pygame 2.5 или новее.

```bash
cd GenerateER
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Запуск с базой данных:

```bash
.venv/bin/python run_editor.py /путь/к/базе.db
```

Запуск без аргументов открывает пустое окно: нажмите «Открыть БД» или перетащите файл `.db` в окно. Другие способы запуска:

```bash
.venv/bin/python -m er_editor /путь/к/базе.db
.venv/bin/python -m er_editor /путь/к/проекту.erd.json
```

Веб-версия запускается так же, отдельная установка не нужна:

```bash
.venv/bin/python run_web.py
```

## Быстрый старт

1. Откройте базу данных: кнопка «Открыть БД», сочетание Cmd+O или перетаскивание файла в окно.
2. Переключайтесь между вкладками «Инфологическая» и «Даталогическая» (клавиша Tab).
3. Кликните сущность — справа появятся её свойства. Двойной клик по тексту правит его на месте.
4. Если диаграмма получилась неаккуратной, перетащите узлы мышью или нажмите «Авто-раскладка».
5. Сохраните проект (Cmd+S) и экспортируйте картинку (Cmd+E).
6. Нужна база данных по схеме? На вкладке «Даталогическая» нажмите «Скачать БД» (Cmd+B); чтобы сразу получить тестовые данные, отметьте чекбокс «5 случайных записей».
7. Хотите рисовать с нуля? Откройте вкладку «Даталогическая», нарисуйте таблицы («+ Таблица»), протяните стрелки связей («Связь»), выберите нормальную форму (1НФ … НФБК) и исправьте то, что подсвечено красным. Затем нажмите «БД и модели» (Cmd+Shift+B): получите базу, обе модели и отчёт. Подробности — в разделе «Проверка нормальной формы».

## Нотация Баркера

Так читается инфологическая диаграмма:

- **Сущность** — прямоугольник со скруглёнными углами, имя в единственном числе.
- **Атрибуты:** `#` — входит в уникальный идентификатор (UID), `*` — обязательный, `o` — необязательный.
- **Связь** — линия из двух половин. Половина у сущности описывает её участие: сплошная — «должен», пунктир — «может».
- **«Воронья лапка»** на конце — «один или несколько», простой конец — «один и только один».
- **Имя связи** пишется у своей сущности. Читается так: «Каждый A **должен** быть *имя у A* **одним и только одним** B» и «Каждый B **может** быть *имя у B* **одним или несколькими** A».
- **Черта поперёк линии** — связь входит в UID сущности (сущность идентифицируется через родителя).
- **Dead crows fly east.** Лапки направлены только вверх или влево: подчинённые сущности стоят левее и выше, главные — правее и ниже.
- Связей «многие ко многим» нет: их заменяет сущность-пересечение.

На диаграмме конец **A** — подчинённая сторона («много», где лежит внешний ключ), конец **B** — главная.

## Как диаграммы строятся из базы данных

### Инфологическая модель

- Каждая таблица становится сущностью с именем заглавными буквами; все имена потом можно переименовать.
- Внешние ключи не показываются атрибутами: их заменяют связи.
- Столбцы первичного ключа получают маркер `#`, столбцы NOT NULL — `*`, остальные — `o`.
- Суррогатный ключ скрывается, если уникальность записи задана целиком внешними ключами (как в таблицах-пересечениях): идентификатором становятся связи, и на них ставится черта UID.
- Связь 1:1 получается, если столбцы внешнего ключа совпадают с первичным ключом или с `UNIQUE`; иначе связь 1:M.
- Половина линии у дочерней таблицы сплошная, если внешний ключ NOT NULL, и пунктирная, если допускает NULL. Половина у родителя пунктирная: у родителя может не быть дочерних записей.
- Имена связей по умолчанию — «относится к» и «включает» (или «имеет» для 1:1); их нужно уточнить вручную.

### Даталогическая модель

- Таблицы показывают все столбцы с колонками «ключ», «имя», «тип», «NOT NULL / NULL».
- Метки ключей: `PK`, `FK`, `U` (может быть несколько через запятую).
- Подпись на линии — правило `ON DELETE` внешнего ключа. Линия привязывается к строке внешнего ключа дочерней таблицы и к строке первичного ключа родителя.

### Автораскладка и маршруты связей

1. Глубина таблицы — длина самой длинной цепочки внешних ключей; колонка = наибольшая глубина минус глубина таблицы. Циклы ссылок разрываются.
2. Порядок таблиц в колонках подбирается по средней высоте соседей, чтобы линий пересекалось меньше.
3. Для каждой связи перебираются стороны узлов и положения среднего звена; каждый вариант получает штрафы за пересечение чужих узлов, длину, изломы, наложение на другие линии, короткие концевые звенья и «лапку» на левой или верхней стороне. Выигрывает вариант с наименьшим штрафом.

Автомаршруты хороши не всегда: если подпись налезла на линию, перетащите подпись, а излом сдвиньте квадратом.

## Создание базы данных

Редактор не только читает схему, но и **создаёт** базу данных SQLite по даталогической диаграмме: кнопка «Скачать БД» (Cmd+B) на верхней панели или в панели справа, когда ничего не выделено.

### Как нарисовать схему с нуля

1. Откройте вкладку «Даталогическая» и нажмите «+ Таблица». Двойной клик по заголовку — название таблицы.
2. Добавляйте строки кнопкой «+ Поле». Для каждой задайте имя, тип (быстрые кнопки INT, TEXT, REAL, DATE или любое имя типа, например `VARCHAR(50)`), NOT NULL и ключи: переключатели PK, FK, UNIQUE.
3. Нажмите «Связь», нажмите на **дочернюю** таблицу (где будет внешний ключ) и протяните стрелку к **родительской**; вместо протягивания можно кликнуть таблицы по очереди. Стрелка идёт от внешнего ключа к первичному, у концов подписано «N» (много) и «1» (один). В дочерней таблице сам появится столбец внешнего ключа `<родитель>_<ключ>` того же типа, что ключ родителя. У родителя должен быть столбец с меткой PK. Вместо стрелок можно вернуть «воронью лапку»: панель справа, «Концы связей».
4. Правило `ON DELETE` выбирается в панели связи кнопками `CASCADE`, `RESTRICT`, `SET NULL`, `SET DEFAULT`, `NO ACTION`; выбранное правило пишется подписью на линии (подпись можно ввести и вручную, любой другой текст означает `NO ACTION`). Что делает правило при удалении записи родителя: `CASCADE` — удаляет и дочерние записи; `RESTRICT` и `NO ACTION` — запрещают удаление; `SET NULL` — записывает `NULL` в столбцы внешнего ключа (они не должны быть `NOT NULL`); `SET DEFAULT` — записывает в них значение `DEFAULT` (его задают в поле «DEFAULT» панели столбца; значение должно существовать в родительской таблице). Если правило противоречит столбцам ключа, в панели связи появляется предупреждение, а при создании базы оно попадает в список предупреждений.
5. Составной `UNIQUE` вводится в поле UNIQUE панели таблицы: столбцы через запятую, группы через «;». Одиночный `UNIQUE` — переключатель у поля.
6. Для связи «один к одному» поставьте у дочернего конца связи кратность «Один»: у столбцов ключа появится `UNIQUE`.
7. Выберите нормальную форму и посмотрите вердикт (раздел «Проверка нормальной формы»).
8. Нажмите «Скачать БД» (только база) или «БД и модели» (база, обе модели и отчёт), выберите имя файла. Исходную базу, из которой импортирован проект, перезаписать нельзя.

### Что попадает в базу данных

| На диаграмме | В базе данных |
|---|---|
| Таблица, название | `CREATE TABLE "название"` (пробелы и кириллица допустимы) |
| Имя и тип поля | Столбец с этим типом; пустой тип — столбец без типа |
| Метка PK | Первичный ключ; одиночный `INTEGER` — `INTEGER PRIMARY KEY` (rowid), составной — табличное ограничение |
| NOT NULL, а также любое поле PK | `NOT NULL` |
| Метка U, составной UNIQUE | `UNIQUE (…)` |
| Связь | `FOREIGN KEY (…) REFERENCES … ON DELETE …`; столбцы берутся из привязки связи, а если её нет — подбираются по именам среди полей с меткой FK |

Поле «DEFAULT» панели столбца переносится как `DEFAULT`: число, строка (текст без апострофов превращается в строковый литерал), `NULL`, `TRUE`, `FALSE`, `CURRENT_DATE`, `CURRENT_TIME`, `CURRENT_TIMESTAMP`; введённый текст не может изменить SQL. Значения `DEFAULT` читаются и из импортируемой базы. `CHECK` и `AUTOINCREMENT` диаграмма не хранит, поэтому в базу они не попадают.

### Случайные данные

Если отмечен чекбокс «5 случайных записей», в каждую таблицу добавляются 5 записей:

- первичные ключи и `UNIQUE` различны у всех записей; целочисленные ключи — 1…5, текстовые — вида `USE1`;
- внешние ключи берутся из записей родительских таблиц, поэтому ссылки всегда корректны; родительские таблицы заполняются первыми, самоссылки и таблицы-пересечения тоже поддерживаются;
- для связей «один к одному» и составных ключей из внешних столбцов подбираются несовпадающие значения;
- значения выбираются по типу и имени столбца: e-mail, телефон, имя, фамилия, город, улица, статус, цена, количество, вес, даты в формате ISO и т. д.; необязательные столбцы примерно в 15 % случаев остаются пустыми (`NULL`);
- без чекбокса создаются пустые таблицы.

После вставки выполняется `PRAGMA foreign_key_check`; нарушения (если они вдруг есть) показываются предупреждением.

### Проверки перед созданием

Схема проверяется целиком, и все найденные проблемы показываются списком: таблица без названия или без полей, повторяющиеся названия таблиц и полей, у родителя нет PK, нельзя определить столбец внешнего ключа, ссылка на столбцы, которые не PK и не UNIQUE. Затем проверяется выбранная нормальная форма: если есть нарушения, программа спросит «Показать нарушения» или «Скачать всё равно». Файл создаётся во временном виде и подменяет итоговый только при успехе, поэтому ошибка не испортит уже существующий файл.

## Проверка нормальной формы

Таблицы вы рисуете сами, в том же окне: названия, столбцы, типы, метки ключей, связи-стрелки. Программа ничего не придумывает и не перестраивает схему, а только **проверяет**, соответствует ли нарисованное требованиям выбранной нормальной формы, и показывает, что именно не так.

### Как пользоваться

1. Нарисуйте таблицы на вкладке «Даталогическая» (раздел «Создание базы данных»).
2. На верхней панели нажмите нужную форму: 1НФ, 2НФ, 3НФ или НФБК. Каждая следующая включает предыдущую.
3. Кнопка справа от них показывает вердикт: зелёная — «соответствует», оранжевая — соответствует, но есть подозрения, красная — «нарушений: N». Клик по ней открывает отчёт справа.
4. Таблицы с нарушениями обведены красной рамкой, затронутые столбцы залиты розовым; подозрения — оранжевым. Справа каждое замечание — карточка «что не так» и «что делать». Клик по карточке выделяет таблицу и столбец на схеме. В панели выбранной таблицы внизу показаны её замечания.
5. Исправляйте схему и смотрите, как меняется вердикт: проверка пересчитывается после каждой правки.
6. «Отчёт в .md» сохраняет результат в файл; «БД и модели» кладёт такой отчёт в комплект.

### Что проверяется

| Форма | Требование | Что считается нарушением |
|---|---|---|
| Схема (всегда) | Схему можно превратить в базу данных | Таблица без названия или без столбцов, повтор названия таблицы, у родителя связи нет PK, не найден столбец внешнего ключа, UNIQUE или зависимость ссылаются на несуществующий столбец |
| 1НФ | Есть первичный ключ, значения атомарны, нет повторяющихся групп | Нет PK; повтор имени столбца; тип ARRAY, JSON, LIST и подобные; группа столбцов `телефон1`, `телефон2` |
| 2НФ | Неключевые столбцы зависят от всего составного ключа | Зависимость от части составного ключа по записанным зависимостям; столбец-копия атрибута родителя (`product_name` в позиции заказа с ключом из `order_id` и `product_id`) |
| 3НФ | Неключевые столбцы не зависят друг от друга | Записанная зависимость, левая часть которой не ключ; копия атрибута родителя при неключевом внешнем ключе (`customer_name` рядом с `customer_id`); пара `X_id` и `X_name` без ключа |
| НФБК | Левая часть любой зависимости — ключ | Записанная зависимость, левая часть которой не ключ, но определяет ключевой столбец |

Показываются также **подозрения** — они не меняют вердикт, их нужно просто оценить глазами: ключ-кандидат следует из зависимостей, но не объявлен; тип столбца не указан; имя похоже на список (`tags`, `phones`, `список_…`) или на составное значение (`ФИО`, `адрес`); столбец назван так же, как атрибут родительской таблицы (`price`); столбец с приставкой части составного ключа (`product_…`); типичные иерархии вроде город → страна; типы внешнего и первичного ключа различаются.

### Зависимости между столбцами

На диаграмме нарисованы только ключи и связи, а «город определяет страну» — смысл данных, который из рисунка не узнать. Поэтому у таблицы есть поле **«Зависимости»** (панель справа при выделенной таблице). Записи через «;» в виде `левая часть -> правая часть`, столбцы через запятую:

```
город -> страна; индекс -> город, область
```

Что с ними делает проверка:

- зависимость, левая часть которой — часть составного ключа, а правая — неключевой столбец, нарушает 2НФ;
- зависимость, левая часть которой не является ключом (и не часть ключа), а правая — неключевой столбец, нарушает 3НФ;
- зависимость, левая часть которой не ключ, а правая — часть ключа, нарушает НФБК (при этом 3НФ может соблюдаться);
- записи с неизвестными столбцами или без стрелки считаются ошибкой схемы; при переименовании столбца записи обновляются сами.
- ключи-кандидаты, которые следуют из зависимостей, но не объявлены (например, при записи `email -> id`), программа находит сама и учитывает как ключи: столбцы таких ключей не считаются зависящими от «чужого» ключа. О каждом таком ключе выдаётся подозрение «Необъявленный ключ» с советом отметить его как UNIQUE, чтобы база данных обеспечила уникальность.

Без записанных зависимостей программа ищет только признаки из таблицы выше, поэтому «соответствует» значит «явных нарушений не найдено», а не «доказано». Для точной проверки 2НФ и 3НФ запишите зависимости.

### Комплект «БД и модели»

Кнопка «БД и модели» (Cmd+Shift+B) спросит имя файла и создаст рядом:

| Файл | Содержимое |
|---|---|
| `<имя>.db` | База данных SQLite по нарисованной схеме, с данными (чекбокс) или пустая |
| `<имя>_datalogical.png` | Даталогическая модель — то, что нарисовано |
| `<имя>_infological.png` | Инфологическая модель (нотация Баркера); если вкладка «Инфологическая» пуста, она строится по таблицам, а нарисованная вручную используется как есть |
| `<имя>_normal_form.md` | Отчёт о проверке: вердикт, достигнутая форма, замечания |

Если схема не соответствует выбранной форме, перед созданием появится вопрос: показать нарушения или скачать всё равно. Кнопка «Построить по таблицам» на вкладке «Инфологическая» (панель справа без выделения) строит инфологическую диаграмму заново; изменение можно отменить.

### Зависимости по данным

Если открыта база SQLite с данными (в веб-версии: «Открыть БД»), в панели таблицы под полем «Зависимости» активна кнопка «Найти по данным БД». Сервер перебирает зависимости `X -> A`, где `X` — один или два столбца, и показывает те, что выполняются во всех прочитанных строках. Отметьте верные по смыслу и нажмите «Добавить отмеченные»: они попадут в поле «Зависимости» и будут учтены проверкой 2НФ / 3НФ / НФБК.

* Данные могут опровергнуть зависимость, но не доказать её: найденное — только кандидаты, решает человек.
* Не рассматриваются таблицы меньше 8 строк, столбцы с одним значением и уникальные столбцы (ключи), левые части с редкими повторами. Остаются только минимальные зависимости. `NULL` считается обычным значением.
* Читается до 5000 строк и 20 столбцов таблицы, поиск идёт не дольше 5 секунд (если время вышло, это написано в окне). База только читается.
* Это точный перебор без ИИ; нормальные формы по-прежнему проверяются по правилам программы. Правильность проверки дополнительно сверяется тестом `tests/test_normalform_random.py` со случайными схемами и независимым перебором ключей.

### Ограничения проверки

- Проверка опирается на записанные зависимости и признаки в именах и связях; по смыслу данных она не может судить о том, чего не знает.
- Признаки по именам рассчитаны на английские и русские названия; для других языков работают только записанные зависимости.
- Ключи-кандидаты — это объявленные PK и UNIQUE и ключи, которые программа выводит из записанных зависимостей (не больше 32 на таблицу). Вывод выполняется только если у таблицы объявлен хотя бы один ключ. Если объявленный составной ключ избыточен (его часть сама определяет таблицу), остаётся и он, и найденный меньший ключ. `CHECK` диаграмма не хранит и не учитывает.
- Четвёртая и пятая нормальные формы (многозначные зависимости) не проверяются.

## Веб-версия

Редактор можно использовать в браузере: интерфейс — страница на HTML и JavaScript, а всё, что уже написано на Python (проверка нормальных форм, автораскладка и маршруты связей, чтение SQLite, создание базы с данными, PNG), выполняет сервер на стандартной библиотеке. Новых зависимостей нет.

### Запуск

```bash
.venv/bin/python run_web.py
```

Адрес печатается в терминале (по умолчанию `http://localhost:8000/`, браузер открывается сам). Параметры: `--port 9000` — другой порт (если порт занят, берётся следующий), `--no-browser` — не открывать браузер, `-v` — печатать журнал запросов, `--host` — адрес прослушивания. Остановка — Ctrl+C. Тот же сервер запускается командой `python -m er_editor.web`.

### Три способа начать

На пустом проекте страница показывает три карточки; те же действия всегда есть на верхней панели:

| Кнопка | Что делает |
|---|---|
| «Новый холст» | Чистая схема для рисования с нуля: открывает вкладку «Даталогическая» и сразу добавляет первую таблицу (если есть несохранённые изменения, спросит подтверждение) |
| «Открыть БД» | Загружает файл SQLite или проект `.erd.json` (можно перетащить файл в окно) |
| «По описанию» | Строит обе диаграммы по описанию — текстом или SQL; после построения их можно править и скачать |

### Диаграммы по описанию

В окне «По описанию» введите текст или вставьте SQL (кнопки «Пример: текст» и «Пример: SQL» подставляют образцы), нажмите «Построить диаграммы» (или Ctrl+Enter). Если исходное описание неясное, кнопка «Промт для ИИ» скопирует в буфер инструкцию вместе с введённым текстом. Её можно отправить внешней нейросети (например, DeepSeek), а полученный результат проверить и вставить в поле. Если построить схему не удалось, под ошибкой есть кнопка «Скопировать промт для ИИ с этой ошибкой»: в промт добавляются причины отказа. Программа сама ничего никуда не отправляет и не обращается к нейросетям: текст попадает во внешний сервис, только если вы сами вставите туда промт. Формат определяется сам: если в тексте есть `CREATE TABLE` — это SQL.

| Запись | Значение |
|---|---|
| `Клиент: имя, email!, телефон?` | Таблица и атрибуты: `!` — уникальный, `?` — может быть пустым, `:тип` — целое, вещественное, текст, дата (без типа он выбирается по названию). Столбец `id` добавляется сам |
| `Клиент 1:N Заказ` | У одного клиента много заказов, внешний ключ — в «Заказ». Также `N:1`, `1:1` (с `UNIQUE`), `Заказ -> Клиент` («Заказ» ссылается на «Клиент»), `1:N?` — ссылка необязательна, «один-ко-многим» |
| `Заказ N:M Товар через Позиция: количество:целое` | «Многие ко многим»: создаётся таблица-связка с составным ключом и своими атрибутами |
| `у одного клиента может быть много заказов` | То же обычной фразой; понимаются также «каждый товар принадлежит одной категории» и «много заказов … много товаров». Как понята каждая фраза, программа показывает после построения |
| `# комментарий` | Строка игнорируется |

Можно писать и **словесным описанием предметной области**, как в курсовой работе: строка `пользователь (Код, Фамилия, Email, Дата рождения)` — сущность, «Код» — первичный ключ, `Код пользователя` в другой сущности — внешний ключ на неё, строка `связь заказ—продукт (Код заказа, Код продукта, Количество)` — таблица-связка. Строки «например, …» и обычные предложения пропускаются и перечисляются в пояснениях; ссылка «Код X» создаётся, только если сущность X описана. Образец — кнопка «Пример: описание предметной области».

SQL разбирается настоящим SQLite: типы, ключи, `UNIQUE` и внешние ключи берутся из `CREATE TABLE`. Выполняются только `CREATE TABLE` и `CREATE INDEX` (без `AS SELECT`) за три секунды, остальные операторы пропускаются и перечисляются в пояснениях. Описание только переводится в схему и не нормализуется: соответствие форме 1НФ … НФБК покажет проверка. Ошибки (неизвестная сущность, непонятная фраза, неверный SQL) выводятся в окне, текст сохраняется.

### Что есть в веб-версии

Всё то же, что в программе: две диаграммы, «+ Таблица» и стрелки связей (протягиванием или двумя кликами), правка текста двойным кликом (курсор подсказывает, что можно двигать или тянуть), цвета, легенда и надписи, undo и redo, масштаб и прокрутка, панель свойств справа, выбор формы 1НФ … НФБК с подсветкой нарушений, поле «Зависимости», «Скачать БД» и «БД и модели», чекбокс «5 случайных записей», «О программе» и справка F1. Горячие клавиши те же, но вместо Cmd — Ctrl (на Mac работает и Cmd); работают на любой раскладке.

Отличия от настольной программы:

| Что | В веб-версии |
|---|---|
| «Открыть БД» | Файл `.db` загружается на сервер (его можно и перетащить в окно страницы); сервер читает схему во временной копии и сразу её удаляет. Можно открыть и проект `.erd.json` |
| «Сохранить» | Скачивает файл `<имя>.erd.json`; формат тот же, проект открывается в обеих версиях |
| «Скачать БД» | Скачивается файл `<имя>.db` |
| «БД и модели» | Скачивается ZIP: `<имя>.db`, `<имя>_infological.png`, `<имя>_datalogical.png`, `<имя>_normal_form.md`; если вкладка «Инфологическая» пуста, она строится по таблицам |
| Экспорт PNG | Рисует сервер тем же кодом, что и программа; файлы скачиваются браузером (Shift + «Экспорт PNG» — обе диаграммы) |
| «Отчёт в .md» | Формируется в браузере и скачивается файлом |
| «Заново из БД» | Работает, пока открыта страница: загруженный файл хранится в памяти браузера |
| Хранение проекта | Проект живёт только в браузере: при закрытии страницы с несохранёнными изменениями браузер предупредит. Сервер ничего не запоминает |

Ширину узлов страница подбирает по шрифту браузера, а PNG рисует сервер шрифтом pygame; на разных системах эти шрифты могут отличаться на несколько пикселей.

### Как это устроено

Сервер без состояния: проект целиком присылается в запросе, ответ — JSON, файл или PNG. Ошибки возвращаются как `{"error": …}`; если схему нельзя превратить в базу данных, добавляется список `problems` (код 422).

| Запрос | Что делает |
|---|---|
| `GET /api/meta` | Версия, названия и требования нормальных форм, число случайных записей, стандартные легенды |
| `GET /api/new` | Пустой проект |
| `POST /api/import` | Тело — файл SQLite; ответ — проект с раскладкой |
| `POST /api/check` | `{diagram, level}` → отчёт о нормальной форме (`normalform.check`) |
| `POST /api/layout` | `{diagram}` → диаграмма с автораскладкой |
| `POST /api/route` | `{diagram, ids}` → стороны и положения концов выбранных связей |
| `POST /api/info` | `{diagram}` → инфологическая диаграмма по даталогической |
| `POST /api/describe` | `{text}` → проект с обеими диаграммами и пояснениями (код 422 со списком `problems` при ошибке описания) |
| `POST /api/fds` | Тело — файл SQLite → кандидаты в функциональные зависимости по данным (`name`, `rows`, `note`, `fds`) |
| `POST /api/database` | `{project, sample}` → файл `.db` |
| `POST /api/bundle` | `{project, sample}` → ZIP с базой, PNG и отчётом |
| `POST /api/png` | `{diagram, scale}` → PNG |
| `GET /api/readme` | Это руководство в виде HTML для окна «О программе» |

Файлы страницы лежат в `er_editor/web/static/`:

| Файл | Назначение |
|---|---|
| `index.html`, `style.css` | Каркас страницы и оформление |
| `geom.js` | Геометрия и ортогональные маршруты связей (порт `geom.py`) |
| `model.js` | Модель проекта (тот же JSON, что у `Project.to_json`), ключи, зависимости |
| `scene.js` | Размеры и геометрия диаграммы, поиск объекта под курсором (порт `Scene`) |
| `draw.js` | Рисование диаграммы в SVG: узлы, связи со стрелками и «лапками», легенда |
| `core.js` | Состояние, операции над схемой, история, обмен с сервером, проверка нормальной формы, скачивание |
| `panel.js` | Панель справа: свойства, отчёт о нормальной форме |
| `app.js` | Холст, мышь, клавиатура, правка текста на месте, панель инструментов |

### Безопасность

По умолчанию сервер слушает только `127.0.0.1` и отклоняет запросы с чужим заголовком `Host`. Размер запроса ограничен 64 МБ, имена скачиваемых файлов очищаются, статические файлы отдаются только из каталога `static`. Авторизации нет: параметр `--host 0.0.0.0` открывает редактор всей сети, используйте его только в доверенной сети.

## Файлы

### Проект .erd.json

Кнопка «Сохранить» (Cmd+S) пишет файл `<имя базы>.erd.json` рядом с базой данных; если базы нет, программа спросит имя. Файл — обычный JSON в UTF-8: обе диаграммы целиком (положение узлов, маршруты, подписи, легенда, надписи), путь к базе, масштаб экспорта и настройка сетки. При следующем открытии той же базы программа спросит, открыть сохранённый проект или импортировать схему заново. Неизвестные ключи при чтении игнорируются.

### Экспорт PNG

Cmd+E сохраняет текущую диаграмму, Cmd+Shift+E — обе (имена заканчиваются на `_infological.png` и `_datalogical.png`). Масштаб ×1, ×2 или ×3 выбирается в панели справа, когда ничего не выделено. Картинка рисуется в удвоенном разрешении и уменьшается — линии получаются сглаженными. Размер ограничен 60 млн пикселей.

| `er_editor/describe.py` | Схема по описанию: текст или SQL → таблицы. Не зависит от pygame |
| `er_editor/web/server.py` | Сервер веб-версии на стандартной библиотеке: API и статические файлы |
| `er_editor/web/static/` | Страница веб-версии: HTML, CSS и модули JavaScript |
| `run_editor.py` | Простой запуск программы |
| `run_web.py` | Запуск веб-версии |
| `tests/` | Автоматические тесты: `python tests/run_all.py` |
| `tools/audit_docs.py` | Аудитор аннотаций типов и докстрингов |
| `tools/experiments.py` | Воспроизводимые опыты: сверка проверки нормальных форм с полным перебором и проверка поиска зависимостей по данным (`python tools/experiments.py`) |
| `generate_er.py` | Первая версия: ручной генератор SVG-диаграмм для базы SportPit.db |

Поток данных:

```
SQLite  ->  schema.read_schema  ->  list[Table]
                                      |
                  schema.build_info / build_data  ->  Diagram
                                      |
                  layout.fit_widths + auto_layout  ->  Diagram с координатами
                                      |
                  render.Scene(Diagram)  ->  геометрия, маршруты, подписи
                                      |
         render.draw_diagram(Gfx)  ->  экран   или   export_png  ->  файл .png
```

Основные решения:

- **Одна модель, два рендера.** Один и тот же код рисует и на экран, и в PNG; разница только в камере и масштабе.
- **Мировые координаты.** Все размеры хранятся в «мировых» единицах, камера переводит их в экранные. Положение конца связи хранится как сторона узла и доля её длины, поэтому связи следуют за узлами.
- **Немедленная отрисовка интерфейса.** Каждый кадр рисует всё заново и собирает список кликабельных областей. Панель справа строится кодом по текущему выделению.
- **История изменений — снимки.** Перед любым изменением модель сериализуется в JSON и кладётся в стек; отмена просто загружает снимок.
- **Правка текста.** Ввод символов приходит событием `TEXTINPUT` (поэтому работает кириллица), служебные клавиши — событием `KEYDOWN`.
- **Диалоги выбора файла** запускаются в отдельном потоке (macOS — `osascript`, иначе tkinter в отдельном процессе), окно не «зависает».

## Типы и программный интерфейс

Весь код аннотирован типами: у каждого параметра и у каждой функции указан тип результата (`-> None`, `-> Box` и т. п.). У каждой функции, метода и вложенной функции есть докстринг в стиле Google: что делает, `Args:` (аргументы с типами), `Returns:` (что и какого типа возвращает) и `Raises:` (какие ошибки возможны).

| Тип | Что это |
|---|---|
| `Project` | Проект: `db_path`, `diagrams: dict[str, Diagram]`, `export_scale`, `grid`, `fill_sample`, `normal_form` |
| `Diagram` | Диаграмма: `kind`, `nodes: list[Node]`, `links: list[Link]`, `legend: Legend`, `notes: list[Note]`, `arrows` |
| `Node`, `Row` | Сущность / таблица (в том числе `uniques` и `fds` — записанные зависимости) и её строка (атрибут / столбец) |
| `normalform.Report`, `normalform.Issue` | Результат проверки и одно замечание: уровень, нарушение или подозрение, таблица, столбцы, что не так, что делать |
| `Link` | Связь: концы A и B, стороны и положения, кратность, участие, черты UID, подписи |
| `Legend`, `LegendItem`, `Note` | Легенда с пунктами и свободная надпись |
| `FRect` | Прямоугольник с вещественными координатами |
| `Scene` | Геометрия диаграммы: `nodes`, `links`, `legend`, `notes` |
| `Fonts`, `Gfx` | Кэш шрифтов и графический контекст с камерой |

Основные функции и то, что они возвращают:

| Функция | Возвращает |
|---|---|
| `schema.read_schema(db_path)` | `list[Table]` — структура БД |
| `schema.build_project(db_path, measure)` | `Project` — обе диаграммы с раскладкой |
| `layout.auto_layout(d)` | `None` — расставляет узлы и маршруты на месте |
| `layout.auto_route(d, only=None)` | `None` — подбирает маршруты связей |
| `geom.route(p1, d1, p2, d2, mid)` | `tuple[list[Point], str or None]` — точки ломаной и ось среднего звена |
| `render.export_png(d, fonts, path, scale)` | `tuple[int, int]` — размер сохранённого PNG |
| `dbgen.diagram_to_tables(d)` | `list[Table]` — схема из даталогической диаграммы; при проблемах `SchemaError` |
| `dbgen.create_database(path, tables, sample_rows, seed)` | `DbReport` — файл SQLite создан, добавлено столько-то записей |
| `normalform.check(d, level)` | `Report` — проверка даталогической диаграммы на форму `level` (1–4); `Report.ok`, `Report.violations`, `Report.achieved` |
| `normalform.format_markdown(report, name)` | `str` — отчёт о проверке в Markdown |
| `Project.load(path)` и `Project.save(path)` | `Project` и `None` — чтение и запись `.erd.json` |

Пример: импорт базы и экспорт картинок без окна программы.

```python
import pygame
from er_editor.render import Fonts, export_png
from er_editor.schema import build_project

pygame.font.init()                      # шрифтам нужен инициализированный pygame
fonts = Fonts()
project = build_project("shop.db", fonts.measure)
export_png(project.diagrams["info"], fonts, "info.png", scale=2)
export_png(project.diagrams["data"], fonts, "data.png", scale=2)
project.save("shop.erd.json")
```

Проверка качества кода:

```bash
.venv/bin/python tools/audit_docs.py
.venv/bin/pip install mypy
.venv/bin/mypy --strict --ignore-missing-imports er_editor generate_er.py
.venv/bin/python tests/run_all.py
```

Первая команда — аудитор `tools/audit_docs.py`: по синтаксическому дереву проверяет, что у каждой функции есть аннотации всех параметров и результата, а в докстринге — разделы `Args:`, `Returns:` и (если в теле есть `raise`) `Raises:`. Он должен сообщать «замечаний: 0». Вторая и третья — статическая проверка типов mypy в строгом режиме. Четвёртая запускает автоматические тесты (`tests/`): проверку нормальных форм, безголовый прогон настольной программы и API веб-сервера; новых зависимостей они не требуют.

Создание базы данных из программы (проект `project` получен, как в примере выше):

```python
from er_editor.dbgen import create_database, diagram_to_tables

tables = diagram_to_tables(project.diagrams["data"])
report = create_database("new.db", tables, sample_rows=5, seed=1)
print(report.tables, report.total_rows, report.warnings)
```

Проверка нормальной формы (то же делает кнопка с названием формы):

```python
from er_editor.normalform import check, format_markdown

report = check(project.diagrams["data"], level=3)
print(report.verdict())
for issue in report.violations:
    print(issue.table, issue.rule, issue.message)
open("normal_form.md", "w", encoding="utf-8").write(format_markdown(report, "shop"))
```

Автоматическая проверка без экрана: переменная окружения `SDL_VIDEODRIVER=dummy` включает режим pygame без окна, а `App.handle(...)` принимает искусственные события мыши и клавиатуры.

## Ограничения

- Выделяется один объект за раз; группой двигать нельзя.
- Автомаршруты не идеальны на больших схемах (десятки таблиц): подписи могут перекрываться, а раскладка занимает несколько секунд.
- Кнопка «Заново из БД» заменяет обе диаграммы схемой из базы и стирает ваши правки (с предупреждением).
- Изменения схемы базы данных не сливаются с правками проекта автоматически.
- На экранах Retina текст интерфейса может выглядеть мягче обычного; в экспортированных PNG это незаметно.
- База данных строится только по даталогической диаграмме; `CHECK`, `AUTOINCREMENT` и индексы (кроме UNIQUE) не переносятся. Правило `ON UPDATE` не поддерживается.
- Работа на Windows и Linux (диалоги через tkinter) не проверялась.
- Веб-версия проверялась в Chromium-подобном браузере; перетаскивание узлов рассчитано на мышь и трекпад, сенсорные жесты (масштаб двумя пальцами) не поддерживаются.

## Решение проблем

| Проблема | Что делать |
|---|---|
| Вместо букв квадратики | В системе нет шрифта с кириллицей из списка Arial, Helvetica, DejaVu, Liberation. Установите один из них |
| Страница пишет «Нет связи с сервером» | Запустите `python run_web.py` и откройте адрес, который он напечатал; страница, открытая как файл, без сервера не работает |
| Не открывается диалог выбора файла | Перетащите файл `.db` в окно или передайте путь аргументом при запуске |
| Не работает вставка в поле | На macOS нужны `pbcopy` и `pbpaste` (есть в системе); иначе используется внутренний буфер |
| Файл не читается как база данных | Откройте файл вручную: `sqlite3 файл.db ".tables"`; программа поддерживает только SQLite |
| Окно «зависло» при экспорте | Большие схемы с масштабом ×3 рисуются несколько секунд; выберите ×2 |
